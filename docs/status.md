# Roastnode Current Status

Last reviewed: 2026-06-13

This is the compact public status ledger for humans and AI agents. It distills the original product context plus the slice docs in this repository. Update it whenever a slice changes what is done or intentionally deferred.

## Built Now

- Rails 8.1 monolith at the repository root, with PostgreSQL, Hotwire, Turbo, Tailwind CSS, Active Storage, Solid Queue, Docker Compose, and local defaults for web port `3001` and PostgreSQL host port `5433`.
- Rails-native authentication, first-user setup for empty installs, password reset, signed-in password change flows, optional user passkeys with browser-picker login and passkey second factor, private-by-default app shell, and an instance admin dashboard with safe read-only checks plus backup controls.
- Workspace core: household onboarding, active workspace switching, owner/admin/member/viewer roles, invite links with optional email delivery and optional username capture during invite signup, accepted invite status display, resend/re-invite for email-bound invites, private invite-only account creation, instance-admin email invites for creating separate new households while public registration remains disabled, member role management/removal, owner-only ownership transfer, owner-only workspace deletion, and workspace-scoped controller patterns.
- Profile settings: display name, username-style display label, avatar, public banner, preferred landing screen, enabled brew methods, grams per coffee spoon for Quick Drip estimates, espresso focus field, hidden espresso fields, number format, and time format.
- Workspace settings: household name, currency, logo, banner, configurable Buy Me a Coffee support badge mode for public shared pages, public brew-share management with URLs, linked brews, edit/remove actions, view counts, and retained recent viewer IP history, and public bean-share management with URLs, linked beans, enabled/protected state, view counts, and retained recent viewer IP history.
- Coffee core: rich beans, equipment, espresso brews, Quick Drip brews for private automatic drip/filter-style daily logging, inventory adjustments, retention markers, dashboard activity, and required-open-bean logging.
- Beans: rich metadata, variety information, search-while-type roaster suggestions from existing workspace bean history, additive photos, primary photo, crop/download/remove media controls, derived bag statuses (`stock`, `open`, `finished`, transitional `used_up`, `archived`), grouped overview sections for open, stock, finished/used-up, and archived bags, active-bag sorting by newest brew use, normal finished-bag lifecycle with `finished_at` and used/days/grams-per-day stats, exceptional issue/archive card, duplicate-as-new-bag, duplicate-label disambiguation, manual inventory adjustment UI, compact overview/detail remaining cards with rating and color-coded remaining bars, curated public bean sharing for publishable opened/finished/used-up bags, and danger-zone delete with dependent brew/inventory cleanup.
- Bean grinder tendencies: bean detail pages always show a grinder tendency card. After a non-duplicated bag has its first brew, the app can suggest a same-grinder adjustment from that first brew's setting, ratio, and total time toward the current espresso target of `1:2.5` in `25-30s`. Suggestions use workspace brew history as comparable context, safe auto-detection for Eureka-style `turn/dial` strings and plain numeric settings, and small relative moves instead of jumping to one absolute historical setting. Blank, inconsistent, or unknown setting strings are skipped instead of raising errors. The card also shows per-bean grinder-setting distribution. New duplicated bags record their source bag, automatic suggestions are suppressed for those bags, and a manual in-card calculation remains available.
- Espresso logging: curated last-brew defaults for bean, grinder, machine, active preparation tools, grind setting, brew temperature, and pre-infusion seconds only, using the user's last active-workspace brew or the workspace's last brew for users without household brew history. Bean weights, dose, yield, total time, first drip, rating, channeling, notes, taste, and photos stay fresh during normal logging. Repeat Good Brew links from private brew details and dashboard cockpit best brews prefill targetable shot/setup values from a selected source brew, use an open duplicated follow-up bag when the source bean is closed, and keep taste, notes, media, and sharing fields fresh. Ground out can prefill dose one way while logging.
- Quick Drip logging: method tabs on the Log screen, profile-enabled methods, brewer equipment, machine cups, coffee spoons or measured ground coffee, spoon-based inventory estimates using the user's grams-per-spoon preference with a 5g fallback, pre-ground bean support, method-scoped preparation tools, Weak/Balanced/Harsh taste labels, and method-specific private Hero Cards without espresso chart/retention.
- External Coffee logging: separate private workspace records for purchased/out-of-home cafe drinks that do not consume bean inventory or require household equipment. External Coffees have a default Log screen tab, dedicated index/detail/edit routes, a broad searchable drink-type catalogue plus workspace-history suggestions, workspace-history place suggestions, optional drink size/place/location capture/price, Brew-style taste/rating controls, private note, public note, private photos, public/private links, photo-forward Hero Cards with workspace/user identity images when present, dashboard/activity participation, mixed Coffees history at `/coffees` with All/Brews/External filters, workspace JSON and CSV export, media ZIP export, and instance backup/restore coverage. Public External Coffee sharing is deferred.
- Recipe profiles: workspace-private espresso recipes can be created from existing brews, preserve public-safe source brew snapshots, expose editable exact targets, structured finish ingredients, finish notes, and one optional private finished-drink photo, and show prominent target markers for grinder, dose, timing, yield, temperature, and watch notes. Creating from a source brew can explicitly reuse the brew's primary photo without auto-selecting it. Recipe-guided logging keeps normal brew defaults unchanged, stores `recipe_id` plus a brew-time `recipe_snapshot`, and renders a subtle Hero Brew Card target ghost. Portable recipe JSON export/import creates unlinked private snapshots with finish ingredients and finish notes, without auto-creating beans, equipment, tools, brews, or media. Public recipe sharing uses unlisted, optionally password-protected token pages with curated snapshots, public finish details, public source notes, public recipe links, and explicitly selected recipe photos served through opaque media handles. Viewers can read recipes but cannot create, edit, delete, export, import, share, or start recipe-guided logging.
- Brew corrections: edit and delete flows keep bean inventory consistent through correction/reversal helpers, while saved taste balance and rating can be adjusted from brew detail with an explicit save.
- Hero Brew Card: dense screenshot-friendly brew card on dashboard and brew details, with safe user labels, avatar/household/equipment marks, bean photo, and method-specific metrics. Espresso cards include ratio, rating, balance, retention, SVG brew chart, first drip, pre-infusion, total time, and vertical temperature label; Quick Drip cards show batch metrics and mark estimated consumed grams with `~`.
- Brew detail pages: full log details below the card plus related bean/equipment/preparation-tool photos and cross-links.

Enabled public espresso shares show native mobile share shortcuts on the private compact Brew Log and brew detail action area. Owners/admins can manage any workspace espresso share; viewers cannot. Public media is served only through the public share whitelist. Workspace settings show public share URLs, linked brews, edit/remove actions, total page views, and a capped recent full-IP view history.

Public bean pages include all espresso and Quick Drip brews for the bag as public-safe compact cards, selected bean package photos only, optional workspace support badge, and refreshed snapshots after public-safe linked data changes. Owners/admins can manage any workspace bean share; viewers cannot. Public media is served only through opaque public bean media handles backed by the share allowlist. Workspace settings show public share URLs, linked beans, enabled/protected state, total page views, and a capped recent full-IP view history.
- Preparation tools: espresso and Quick Drip method-scoped checklist records with ordering, owner/admin-only lifecycle and media management, member-visible tool use in brew logging, brew snapshots, and detail analytics.
- Equipment: grinder, machine, and brewer records with owner/admin-only edit/archive/reopen/delete lifecycle and media management, member-visible gear details, list photos, detail analytics, and historical brew safety when equipment is deleted.
- Equipment events: first-class maintenance logs with grinder, machine, and brewer service event types, multiple affected equipment records, photos, edit/delete, Gear overview logging entry point, equipment detail history, and dashboard activity.

## Changed From The Initial Idea

- Recipes were narrowed from the original broad v1 idea. The current implementation starts with exact-target recipe profiles, guided logging overlays, Hero Card ghost comparison, JSON portability, and curated public recipe pages. Machine-readable profile files remain a separate follow-up slice.
- Backups were originally framed as documentation plus workspace export. The current v1 direction now needs an in-app, instance-admin-only backup system with scheduled jobs, full reconstructable archives, and readable all-households JSON.
- Last-brew defaults were narrowed after product testing. The current contract copies only setup fields: bean, grinder, machine, preparation tools, grind setting, temperature, and pre-infusion seconds.
- Beanconqueror compatibility means practical import first, not round-trip parity.
- Quick Drip v1 intentionally covers private automatic drip/filter-style daily logging. Quick Drip brews can appear as public-safe summaries inside public bean shares, but standalone public Quick Drip brew share pages, Quick Drip recipes, Beanconqueror Quick Drip import, brewer cup/water calibration, and professional filter methods remain deferred.
- The first analytics implementation is server-rendered/query-backed. ECharts/Stimulus interactivity remains optional future work.
- Public identity images are now split by context: normal app media stays private behind authenticated routes, while workspace logos and user avatars referenced by enabled public brew, bean, or recipe share snapshots can render through the relevant public share media whitelist.
