# Mobile-First UI Refresh Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the approved mobile-first Roastnode UI refresh for navigation, dashboard, per-user themes, and the Log Espresso form without changing the Hero Brew Card.

**Architecture:** Keep the Rails monolith and Hotwire view layer. Add a small shared app shell/navigation partial, CSS theme tokens, and focused ERB updates for the dashboard and brew form. Store theme choice on `User` so visual mode is an account preference rather than a browser-only setting.

**Tech Stack:** Rails 8.1, ERB, Tailwind CSS via `tailwindcss-rails`, PostgreSQL, Active Storage private media routes, Minitest integration/model tests.
